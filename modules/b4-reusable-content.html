Navigation and footer

Adding “Mortgages” to the menu should not need a release, or edits to every page. On EDS, the menu is one document that authors own.

The site header and footer come from their own documents, /nav and /footer. They are published separately from pages and loaded in the lazy phase, so a change reaches every page once you preview and publish that one document.

In the boilerplate, the nav document has three sections, in order: brand, sections and tools. A page can point to a different nav document with nav metadata.

Fragments

Legal updates a disclosure that appears on 60 product pages. With a fragment, they change it once.

A fragment is reusable content, authored as its own document or spreadsheet and referenced from many pages. Header and footer are fragments that the boilerplate loads for you. Code can also load fragments based on metadata, and authors can place a Fragment block that points to one.

Fragments are delivered as separate resources, so they cache independently. They are not part of the page’s initial HTML, so do not use them for the page’s main content. aem.live describes correct use as non-canonical content that appears on many pages.

Templates

All article pages should share a layout, without authors rebuilding it every time. On EDS, “template” means something simpler than in traditional AEM.

Set template metadata and the boilerplate adds it as a class on <body>. Developers use that class for styling and auto-blocking. Set it on one page, or across a folder with bulk metadata.

Starter documents are a separate idea: a document to copy, so that new pages begin with the right structure. Experience Workspace also offers library templates (module B6).

Hands-on lab: build a reusable site frame

Goal

Create the header, footer and a shared fragment, then apply a template.

You need

A tutorial site you can publish to.

Time

About 45 minutes

  1. Open /nav and add a menu item with a dropdown.
  2. Preview and publish it, then check two pages.
  3. Edit /footer and publish it.
  4. Create a fragment at /fragments/disclosure.
  5. Reference it with a Fragment block on two pages.
  6. Set a template and confirm the class on <body> in DevTools.

Expected result

One change to the fragment or nav updates every page that uses it.

How to verify

Update the fragment once, publish it, and see the new text on both pages.

Stretch

Use nav metadata to give one page an alternative menu.

  • Nav updated and published
  • Footer updated
  • Fragment reused on two pages
  • Template class confirmed

Enterprise lens

Ownership. Name owners for nav, footer and legal fragments, because one edit affects the whole site.

A nav or fragment publish goes live on every page at once. Review it on preview across several templates.

Header and footer load after the critical path. Avoid putting heavy media in them.

Keep menu labels short and link text meaningful. Test dropdowns with a keyboard.
