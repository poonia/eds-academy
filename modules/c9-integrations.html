Analytics and tags

The business needs measurement, and visitors need speed. The two can coexist.

aem.live documents two main routes: the Adobe Experience Cloud stack (Web SDK, Analytics, Target or AJO, Client Data Layer and Tags), and Google Analytics with Tag Manager.

Load them in the delayed phase, after consent. Avoid head.html. EDS’s Operational Telemetry already covers operational performance data, so check whether an extra tool is needed before adding one.

Consent management

If consent is wrong, it is a legal problem as well as a technical one.

In the current boilerplate, consent-check.js determines consent, dispatches a consent.update event, and imports consented.js once it is granted. It ships as a dummy that declines by default.

Replace it with your CMP; aem.live has worked examples for OneTrust and Cookiebot. The ?consent=accept parameter exists for testing only, and should go when a real CMP is added.

SymptomCauseFix
Analytics never firesDummy gate still in placeImplement a real CMP.

External APIs

A rate calculator needs live data, and an API key must never reach the browser.

aem.live’s guide matches the runtime to the need. For live traffic, use standard API integrations from the front end, or edge workers on your CDN. For author-side operations, use edge workers or App Builder. For dynamic pages, use the BYOM overlay.

Anything in client code is public, so proxy protected APIs. Handle slow and failing responses, and keep calls out of the critical path.

Adobe Target

Personalization has a cost that lands directly on LCP.

Target can be integrated through the Experience Platform Web SDK, which is the recommended route, or the legacy at.js. Modifications apply to the final markup, after blocks are decorated.

The call to Target happens in the eager phase and affects LCP. Applying changes can cause flicker, and code reacting to Target changes needs a MutationObserver. aem.live suggests checking its native experimentation first.

Hands-on lab: add a tag behind consent

Goal

Load a test tag only after consent.

You need

A branch and DevTools.

Time

About 60 minutes

  1. Read consent-check.js.
  2. Open a page and confirm consented.js is not requested.
  3. Add ?consent=accept and confirm that it is.
  4. Add a harmless test script to consented.js.
  5. Check the CSP and adjust through review.
  6. Run PageSpeed Insights.
  7. List what a real CMP must replace.

Expected result

A tag that loads only with consent.

How to verify

The Network panel shows no tag requests without consent.

Stretch

Listen for consent.update in a block.

  • Gate understood
  • Tested both states
  • CSP handled
  • Performance checked
