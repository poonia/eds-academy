Analytics and tags

The business needs measurement, and visitors need speed. The two can coexist.

aem.live documents two main routes: the Adobe Experience Cloud stack (Web SDK, Analytics, Target or AJO, Client Data Layer and Tags), and Google Analytics with Tag Manager.

Load them in the delayed phase, after consent. Avoid head.html. EDS’s Operational Telemetry already covers operational performance data, so check whether an extra tool is needed before adding one.

Consent management

If consent is wrong, it is a legal problem as well as a technical one.

In the current boilerplate, consent-check.js determines consent, dispatches a consent.update event, and imports consented.js once it is granted. It ships as a dummy that declines by default.

Replace it with your CMP; aem.live has worked examples for OneTrust and Cookiebot. The ?consent=accept parameter exists for testing only, and should go when a real CMP is added.

When the banner appears

Since consent-check.js runs in the delayed phase, the banner typically appears a few seconds after load. aem.live calls this intentional. If legal requirements mean the banner must show immediately, load the CMP’s banner script earlier, from loadEager(), while keeping the tracking code itself inside consented.js. That is a decision to make with your privacy team, and you should measure its cost.

Analytics never firesDummy gate still in placeImplement a real CMP.

External APIs

A rate calculator needs live data, and an API key must never reach the browser.

aem.live’s guide matches the runtime to the need. For live traffic, use standard API integrations from the front end, or edge workers on your CDN. For author-side operations, use edge workers or App Builder. For dynamic pages, use the BYOM overlay.

Anything in client code is public, so proxy protected APIs. Handle slow and failing responses, and keep calls out of the critical path.

Adobe Target

Personalization has a cost that lands directly on LCP.

Target can be integrated through the Experience Platform Web SDK, which is the recommended route, or the legacy at.js. Modifications apply to the final markup, after blocks are decorated.

The call to Target happens in the eager phase and affects LCP. Applying changes can cause flicker, and code reacting to Target changes needs a MutationObserver. aem.live suggests checking its native experimentation first.

Limiting the cost

Enable Target only on the pages that run an activity, for example from a metadata flag. Pages with no activity then pay nothing. Keep rules simple, since custom JavaScript in a rule runs on your visitors’ devices. E2 covers this in depth.

Data layers and tracking events

A tag can only report what the page tells it. A small, deliberate set of events keeps analytics useful, and blocks free of vendor code.

Blocks should announce what happened, without knowing who is listening. Dispatch a custom event or push to a data layer, and let consented.js connect those to your analytics vendor. Then replacing a vendor means changing one file.

Name a small set of business events, such as form started, form submitted and CTA clicked, and write them down with their properties. Do not send personal data. Remember that events fired before the tag has loaded are lost unless you queue them. A data layer array handles this naturally, since it can be read later.

Adobe’s stack uses the Adobe Client Data Layer for this, and Google’s uses window.dataLayer. Operational Telemetry already records page views and performance, so tracking those twice has little value.

The protected API proxy pattern

Anything shipped to a browser is public. When an API needs a key, something trusted has to sit in between.

Put a small proxy on your CDN’s edge workers, or on a serverless platform such as App Builder. The browser calls your own origin, and the proxy adds the secret and calls the API. Because the path is on your own domain, you avoid cross-origin setup.

Do not make it a general passthrough. Allow only the specific paths and methods that the front end needs. Validate inputs, set a timeout, and return a safe error. Cache a response only if it is identical for every visitor, and never cache anything personal in a shared cache.

Key visible in the Network panelCalled from the browserMove the call to a proxy.
Open relay abuseProxy accepts any URLAllowlist paths and methods.
Page waits on a partnerNo timeoutSet one, and handle failure.
