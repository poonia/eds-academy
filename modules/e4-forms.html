AEM Forms on EDS

Forms are where visitors become customers. Forms that load slowly, or are hard to complete, lose them.

Edge Delivery Services for AEM Forms uses plain HTML, CSS and JavaScript, with no pipeline to wait for. A valid AEM Forms licence is required. There are two authoring methods.

Document-based authoring builds simple forms in Excel or Google Sheets, with rules and validation, attachments, and submission to a spreadsheet or email. WYSIWYG authoring, using Universal Editor, adds the advanced rule editor, client-side extensibility, reCAPTCHA, document of record, Form Data Model and many submission targets.

Adobe’s Forms overview recommends starting new form projects in Universal Editor, unless the team is entirely document-centric and the form is very basic. The Forms Submission Service can save submissions directly to OneDrive, SharePoint or Google Sheets.

Enterprise forms

A loan application is more like a small application than a web page. Its logic, data and audit trail all need design.

The Rule Editor gives authors conditions and actions without code. Patterns include When/Then, Set If and If/Then/Else. It is an extension that must be enabled in Extension Manager. Rules run from top to bottom. Custom functions go in /blocks/form/functions.js, and must be synchronous.

Available submission targets include spreadsheet, email, REST endpoint, SharePoint, OneDrive, Azure Blob Storage, Power Automate, AEM Workflow, Marketo Engage and Adobe Experience Platform. Check the list for your environment: Adobe’s submit action page is not fully consistent, and custom submit actions are listed as early access.

Client-side rules improve the experience. They are not security. Always validate submitted data on the server, protect from spam, minimize the personal data you collect, and agree on retention.

Hands-on lab: design an eligibility form

Goal

Plan a form with conditional logic and a safe submission path.

You need

A Forms-licensed environment if available. Otherwise, do it on paper.

Time

About 2 hours

  1. Write the purpose, and the data you truly need.
  2. Pick an authoring method.
  3. List fields and validation messages.
  4. Write rules as When/Then.
  5. Choose a submission target and owner.
  6. Define server-side validation.
  7. Test keyboard use and error messages.
  8. State how long data is kept.

Expected result

A form specification ready to build.

How to verify

Each field has a reason, each rule has a test case, and data has an owner.

Stretch

Build it in the sandbox, and measure completion with telemetry.

  • Data minimized
  • Rules listed
  • Server validation planned
  • Retention agreed

Enterprise lens

Decide the system of record. A spreadsheet is fine for a newsletter, and wrong for a regulated application.

Forms often gather personal data. Involve privacy and legal teams before launch.

Every field needs a real label, and errors must be clear and programmatically linked.

Keep form scripts out of the first load unless the form is the main content.
