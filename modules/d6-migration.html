Discovery and inventory

You cannot estimate a migration you have not counted. Most overruns come from page types nobody listed.

Begin with real data: the sitemap, analytics, Search Console and your CMS. Group URLs by page type, then record traffic, backlinks, owner and a decision: keep, merge, retire or rebuild. Do not migrate what nobody visits.

Add Operational Telemetry to the existing site as early as you can, so that you have a performance baseline. Also list integrations, forms, personalization and tags, because those often take longer than pages. Check site size against platform limits, such as 50,000 pages per index and 100,000 redirects.

Component-to-block mapping

A one-to-one port of old components brings old complexity with it. Mapping is where you simplify.

List each old component with its variants and frequency, then decide. Many become default content such as headings, text, images and links. Others become an existing block, a block with a variant, or occasionally a new block. Few should become custom.

Keep content models intuitive for authors. Adobe advises importing an example of each page type early, so that authors can confirm the result makes sense. HTL, Sling models and traditional clientlibs do not carry over, so component code is rewritten.

Content import

Manual copy-paste works for ten pages. For thousands you need repeatable rules.

Run aem import to open the importer at localhost:3001. It works only in Chrome-based browsers. It takes the page DOM, applies transformation rules from your import.js, and creates docx for SharePoint or Google Drive, HTML for Document Authoring, or a JCR package for AEM authoring.

Use the Workbench to refine rules on single pages, then the Bulk tool for lists. Heavy single-page apps can crash the browser after 60 to 100 pages. Turning off JavaScript, when the content is in the markup, can help. For 10,000 or more URLs, contact the AEM team.

JCR packages contain content only. Use the generated asset-mapping.json and the AEM Import Helper to bring across the assets.

URL and SEO preservation

A migration can lose years of search value in a single afternoon. Keeping URLs is the cheapest protection.

Keep URLs wherever you can. EDS document names produce lowercase URLs with only letters, numbers and dashes, and extension-less HTML. If old URLs ended in .html or used capitals, they need planning.

Use the redirects sheet, built from Search Console’s most valuable backlinks and from actual traffic. Check for loops, chains and redirects into 404s. Canonicals must return 2xx. Carry over titles, descriptions and structured data.

OldNewAction
/About-Us.html/about-us301 redirect
/news/2019/item/news/item301 redirect
/promo-2017Nothing relevantAllow a 404
/products/x/products/xNo change

Do not redirect every retired URL to the home page. Search engines may treat those as soft 404s, and visitors do not get what they wanted.

Parity QA and cutover

“Looks the same” is not an acceptance test. Agree what parity means before anyone starts testing.

Define parity by page type, across content, SEO, analytics, accessibility, performance and integrations. Test all high-traffic pages and a sample of each type, on .aem.live. Agree on deliberate differences in writing.

Migrate in stages where possible. Akamai or Cloudflare can route some paths to EDS. With AEMaaCS, origin selectors can proxy parts of a domain. Plan rollback at the CDN. Freeze content, or run a delta import for changes since the main import.

AEM Sites to EDS with UE

Many teams want modern delivery but must keep AEM authoring, governance and workflows. This route allows that, though components still change.

Keep AEM author and use Universal Editor, with the xwalk boilerplate. Blocks replace HTL components, and component models describe their properties. Existing page content must be transformed to the new structure. The importer can produce JCR packages, placed under /content, with assets under /content/dam.

Path mapping connects AEM paths with public URLs, and decides what is published. Publishing runs pre-publish validations covering permissions, reserved paths and images. Images over 10,000 pixels on a side cannot be processed on the fly. You can also move part of a site through a proxy from your existing Cloud Service environment.

Hands-on lab: migrate three page types

Goal

Prove a repeatable import on a small sample.

You need

A public test site you may copy, and an EDS project.

Time

About 3 hours

  1. Inventory 20 URLs and group them by type.
  2. Map their components.
  3. Run aem import, and test one page.
  4. Write rules in import.js.
  5. Have an author review the output.
  6. Bulk import the rest.
  7. Create redirects, and validate them.
  8. Compare old and new against your parity list.

Expected result

A sample migration with documented rules.

How to verify

Imported pages preview with the expected blocks, and redirects land on real pages.

Stretch

Create a delta import for changed pages.
