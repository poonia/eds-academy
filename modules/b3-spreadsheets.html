Spreadsheets as JSON

The branch finder needs 400 locations that change weekly. A spreadsheet the operations team already understands can be the data source, with no database.

Preview a spreadsheet and EDS serves it as JSON at the matching .json path. A single sheet comes back in sheet format, with total, offset, limit, columns and data. The first row supplies the column names.

In a workbook with several sheets, only those prefixed shared- are delivered, so working sheets stay private. shared-default is delivered as a single sheet, and ?sheet=name requests shared-name. Several shared- sheets with no default use multi-sheet format. A response cannot exceed 6 MB compressed, so large data needs limit and offset.

SymptomCauseFix
Internal notes are publicSingle-sheet workbook is always deliveredAdd a sheet so shared- applies, or move the notes.
Data is cut offA default limit or the 6 MB ceilingPage through with limit and offset.

Bulk metadata

Every page in the insights section needs the same theme and share image. Setting it once beats editing 300 documents.

Create a sheet named metadata (or metadata.xlsx in SharePoint) in the content root. A URL column holds a pattern such as /docs/**; every other column is a metadata property.

The sheet is read from top to bottom, and site-wide rows set to ** must come before more specific ones. A page’s own Metadata block beats the sheet. Use "" as a value to explicitly remove a property. Preview and publish the sheet for changes to take effect.

Redirects

A renamed product page is linked from three years of emails. A redirect keeps those links and their search value.

Manage redirects in a sheet called redirects (redirects.xlsx in SharePoint) in the project root, with Source and Destination columns. A source is a relative path; a destination is a relative path or a full URL.

Redirects take precedence over content, so a redirect hides a page at the same URL. In a multi-sheet workbook, only the sheet called helix-default is used. Wildcards are not supported in this sheet; aem.live recommends creating redirects from real usage data.

Placeholders

The “Apply now” button appears in 40 places and in French. Placeholders let a team change the text once.

Placeholders are site-wide strings managed in a sheet named placeholders (placeholders.xlsx in SharePoint), in the root or a locale’s root folder. It needs Key and Text columns.

Developers read the values in code. Placeholder support now lives in the block collection rather than the boilerplate, so check that your project uses it.

Query index

The insights landing page must list the latest articles by itself. The query index is what makes that possible.

A query index keeps a list of published pages, usually at /query-index.json, for lists, feeds, search and filtering. The easiest way to set one up is the Index Admin tool, where you name the properties to extract, such as title, image, description and lastModified.

Pages are indexed when they are published, and unpublishing removes them. Previewed-only pages are never included. Spreadsheet-based indexing works only with Google Drive or SharePoint, not with Document Authoring, AEM Sites or BYOM sources.

Sitemaps

Search engines find new pages faster with an accurate sitemap, and EDS keeps one up to date by itself.

With no configuration, every site gets a /sitemap.xml of its published documents. For custom needs, you can generate one from an index or configure sitemap.yaml through the configuration service. A single sitemap is limited to 50,000 URLs and 50 MB uncompressed.

Setting robots metadata to noindex keeps a page out of the sitemap. The domain comes from cdn.prod.host in site configuration. robots.txt is set in site configuration and is only served on your production domain; aem.page and aem.live hosts are blocked from crawlers.

Taxonomy and tags

Without agreed tags, “RRSP”, “RRSPs” and “Retirement Savings” fragment the article filters. A taxonomy gives everyone one list.

A taxonomy is a controlled list of tags. In AEM authoring, you create tags in the Tagging Console, then a page from the Taxonomy template exposes their descriptions in every language, because the Universal Editor works only with tag IDs.

On document-based sites, teams commonly keep the approved list in a spreadsheet served as JSON and set tags in metadata. That is a project convention, so agree on it with your developers. Tags reach the query index through the article:tag meta tag.

Hands-on lab: run a section from spreadsheets

Goal

Control metadata, redirects and a list from sheets.

You need

A tutorial site you can publish to.

Time

About 75 minutes

  1. Create a data sheet, preview it, and open its .json URL.
  2. Add a second sheet and see how the shared- prefix changes the response.
  3. Add a bulk metadata row for one folder, then publish it.
  4. Add a redirect for a renamed page and test it on preview.
  5. Create a query index with title, description and image.
  6. Publish two pages and open /query-index.json.
  7. Open /sitemap.xml and find them.

Expected result

JSON, metadata, a redirect and an index that all reflect your sheets.

How to verify

Each change appears at the URL you expected, and a noindex page is missing from the sitemap.

Stretch

Use limit and offset to page through your data.

  • Bulk metadata applied
  • Redirect tested
  • Index and sitemap checked

Enterprise lens

Change control. Redirect and metadata sheets affect many URLs. Treat edits like releases, and name an owner.

Anything in a delivered sheet is public. Never store personal or internal data there.

Fetch only the rows you need. Large indexes slow every page that loads them.

Shared strings in placeholders are also what screen reader users hear. Review them for clarity.
