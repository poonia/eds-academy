Creating a site

A project that starts from the wrong template or the wrong owner account costs weeks to correct later.

A site combines code, content and configuration. The first site in an organization usually starts with the developer tutorial: create a repository from the boilerplate, install the AEM Code Sync GitHub app, and connect a content source.

That first step also creates your aem.live organization, named after the GitHub organization. The GitHub user who added the app becomes its admin. For later sites, you can use tools.aem.live or the configuration API.

Choose the boilerplate to match your authoring method. Document-based authoring and Experience Workspace use adobe/aem-boilerplate. AEM authoring with Universal Editor uses adobe-rnd/aem-boilerplate-xwalk.

Cloud Manager EDS sites

Licensed customers often expect domains and certificates to be handled in one place. Cloud Manager can do that, but the choices differ by deployment type.

If you have licensed Edge Delivery Services, you can onboard a site in Cloud Manager and go live through a guided flow. It also brings domain names, SSL certificates and CDN mappings together with your other AEM properties.

There are two deployment types for the Adobe-managed CDN. With an existing AEM as a Cloud Service environment, you proxy all or part of a domain to Edge Delivery. Without one, called an Edge environment, Edge Delivery stands alone.

The difference matters. Experience League, updated 29 September 2026, says the configuration pipeline is available for Cloud Service environments and only through a limited beta for Edge environments. If you need advanced CDN rules on an Edge environment, confirm your access first.

Org and site naming

Names become part of every preview URL, and the wrong one can hit a hard length limit.

An aem.live organization must also exist on github.com, with at least one repository synced through Code Sync. This stops anyone from claiming a name they do not own. If Adobe or a partner creates that GitHub organization for you, it must still have an owner from your company.

Preview and live hosts follow <ref>--<site>--<org>. Special characters become a single dash. A DNS label can have at most 63 characters, and the whole combination must fit in one label, so long branch names can break.

In repoless projects, one canonical site must match its GitHub owner and repository exactly. Code association and CDN push invalidation depend on it.

main--website--acme19Fine

Team onboarding

Launch delays usually come from access requests, not code.

Treat access as a work package with an owner. Developers need the repository, the local CLI and a Sidekick install. Authors need the content source and Sidekick. Administrators need a sign-in with the right role, plus tools.aem.live.

By default, authors do not need to sign in to use Sidekick. Adding role mappings enforces sign-in, so plan the two together.

Adobe can set up a dedicated Microsoft Teams or Slack channel for questions and launch coordination. Request it through your Adobe account team, early in the project.

Run a 30-minute “first preview” session in week one. It finds access problems while they are still cheap.

Hands-on lab: onboard a small team to a test site

Goal

Set up a site, and prove each role can do its job.

You need

A GitHub organization you control, a content source, and a colleague to act as author.

Time

About 90 minutes

  1. Write down the owner, the authoring method and the site name.
  2. Create a repository from the right boilerplate.
  3. Install AEM Code Sync on that repository only.
  4. Connect the content source and preview a page.
  5. Add roles, starting with your own admin role.
  6. Have your colleague preview a test page as an author.
  7. Try to publish as that author, and confirm it is refused.

Expected result

A working site with tested access.

How to verify

The preview URL shows your page, and a user with only the author role cannot publish.

Enterprise lens

Own your accounts. The GitHub organization needs a company owner, even when a partner builds the site.

Install Code Sync only on the repositories that need it. It requests write access to some repository features.

Include any assistive technology your authors use when you test Sidekick and the editor.

Turn on the PageSpeed pull request check from day one, so that the baseline starts at 100.
