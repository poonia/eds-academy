Component definitions

If it is not defined, authors cannot add it. Definitions are the Universal Editor’s catalogue.

component-definition.json lists what can be added. Each entry has a title, an id and an xwalk plugin section with a resource type and template.

A block normally uses core/franklin/components/block/v1/block. Its template sets name, shown as the block name, and model, which links to its fields.

PropertyPurpose
idUsed by filters
template.nameBlock name, which maps to code
template.modelWhich fields to show
SymptomCauseFix
Editor adds an empty blockTemplate has no modelSet template.model.

Models and field types

The model is the author’s form. Field names also decide the block’s HTML.

A model has an id and fields. Common component types include text, richtext, reference, select, boolean and number. Check the current field list for the full set.

Field collapse combines properties by suffix: Title, Type, MimeType, Alt and Text. So imageAlt becomes the alt of image, and headingType sets the level of heading. Element grouping uses an underscore, so teaserText_title goes into the teaserText cell.

FieldsResult
image + imageAltA picture with alt text
link + linkText + linkTypeA styled link
heading + headingTypeAn h2, for example
classesBlock options
SymptomCauseFix
Extra text appears in HTMLSuffix mismatch; names are case sensitiveUse the exact suffix.
A cell has unwanted contentGroup namingUse one group prefix per cell.

Filters

Filters keep pages consistent by limiting what goes where.

A filter has an id and a list of components. Container definitions refer to a filter by id. Add a block to the section filter to make it addable to sections.

Keep the lists tight. A smaller Add menu is easier for authors and easier to govern.

SymptomCauseFix
Block not addableFilter is missing itAdd its id.

Per-block model files

One huge JSON file makes every pull request a merge conflict. Per-block files avoid that.

In the xwalk boilerplate, each block has blocks/hero/_hero.json with its own definitions, models and optional filters. Shared items live under models/.

npm run build:json uses merge-json-cli to create the three root files, and a Husky hook runs it on commit. The root files are generated, so never edit them by hand.

BenefitWhy
Fewer conflictsA block’s model changes in its own file
ReviewableChange sits beside the code
ReusableCopy a block folder whole
SymptomCauseFix
Hook did not runDependencies not installedRun npm install.

Container blocks

Cards hold many cards. Container blocks model that.

A container block has its own properties and children. In the markup, its properties come first as single-column rows. Then each child is a row, with each of its properties as a column.

The container’s template sets a filter that allows its child type. A child uses the resource type core/franklin/components/block/v1/block/item.

SymptomCauseFix
Cannot add a childNo filter on the containerSet template.filter.

Instrumentation

The editor needs to know which element belongs to which content. Lose that link, and in-place editing breaks.

The Universal Editor uses data-aue-* attributes on elements, and semantic element attributes in the boilerplate’s helpers. When your decorate moves content into new elements, those attributes must move as well.

The xwalk boilerplate provides moveInstrumentation(from, to) in scripts.js for this reason.

SymptomCause
Cannot select an item in the canvasAttributes left on the old element
Edit changes the wrong itemAttributes copied, not moved
SymptomCauseFix
Edits do not stickLost instrumentationMove attributes during decoration.

UE extensions

Sometimes authors need a custom picker or a data lookup in the editor.

The Universal Editor can be extended through Adobe’s extensibility model, commonly using App Builder. Examples include custom field types and side panels.

Treat an extension as a product: it has authentication, hosting and upgrade costs. First see whether a model field type, a filter or a Sidekick plugin solves the problem.

Extension APIs change. Check Experience League for the current extension points before you plan one.

SymptomCauseFix
Extension broke after an updateDependent on unstable detailsUse supported extension points.

Hands-on lab: build a Universal Editor block

Goal

Add a quote block that authors can edit in place.

You need

An AEM sandbox with the xwalk template, or a code walkthrough.

Time

About 2 hours

  1. Create blocks/quote/_quote.json.
  2. Define the definition and model.
  3. Add it to the section filter.
  4. Run npm run build:json.
  5. Push to a branch.
  6. Add the block in the editor and fill in its fields.
  7. Decorate it in quote.js with instrumentation intact.
  8. Confirm in-place editing still works.

Expected result

A working block in the editor.

How to verify

You can select and edit each part in place, and the live page is correct.

Stretch

Turn it into a container with several quotes.

  • Definition created
  • Model created
  • Filter updated
  • JSON built
  • Editing still works

Enterprise lens

Contract. Models are a contract with authors. Plan migrations before you rename fields.

Renaming a field can orphan existing content. Add new fields and migrate on purpose.

Require alt text and heading levels through the model.

Field design shapes markup. Keep it simple and let blocks remain light.
