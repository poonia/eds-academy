Spreadsheet-based forms

A branch needs a “Book a consultation” form this week. A spreadsheet can define it without a form-building project.

With document-based authoring, each row of a spreadsheet defines a form field and a block on the page renders it. This suits simple forms with basic fields and quick data connectivity. The Forms Submission Service can save submissions to OneDrive, SharePoint or Google Sheets, even if the spreadsheet is not otherwise managed by EDS.

Available columns and field types depend on the form block in your project. Use of Edge Delivery Services for AEM Forms requires a valid AEM Forms license.

AEM Forms on EDS

A mortgage application has branching logic, attachments and archival rules. A simple spreadsheet will not stretch that far.

WYSIWYG authoring with the Universal Editor suits complex forms that need multiple panels, business logic, data integration and AEM Workflows. It adds an advanced rules editor, a document of record for tamper-proof archives, and reCAPTCHA integration.

Both routes offer accessible components, rules and validations, file attachments, custom components and submission to spreadsheets or email, with performance monitored through Operational Telemetry.

Experiments

Two headlines, one argument. An experiment replaces opinion with evidence.

In an experiment, the control is the current page and a challenger is a variation. By convention, put challengers in /experiments/<id>/. On the control page, add Experiment and Experiment Variants metadata rows.

Traffic splits evenly by default, and can be overridden. The preview shows an overlay for switching variants. Publish the control and every challenger to start, and exclude challengers from search with noindex,nofollow. Measurement uses real user data.

Audiences and campaigns

An email offer should land on the matching page, and a phone visitor may need something different.

Adobe’s experimentation plugin can serve variations by audience or campaign. Developers define audiences in code as functions that return true or false, such as mobile or desktop. A Campaign: Xmas metadata row points to a variant, chosen with ?campaign=xmas or ?utm_campaign=xmas.

The plugin’s documentation says it is available in collaboration with AEM Engineering, so confirm access first. Audiences that rely on external services delay rendering, so favour what the browser already knows.

Hands-on lab: build a form and plan an experiment

Goal

Create a form definition and an experiment plan.

You need

The simulators above, and a tutorial site if available.

Time

About 60 minutes

  1. Sketch the form and remove any field you do not need.
  2. Build the sheet in the simulator, and resolve every issue it shows.
  3. Decide the route with the decision tree.
  4. Write a hypothesis: “Changing X will improve Y because Z.”
  5. Create an experiment ID and folder name.
  6. Draft the control page metadata.
  7. Estimate traffic with the split visual.

Expected result

A validated form definition, and an experiment plan with metadata.

How to verify

The form has labels for every field, and the plan names one measure of success.

Stretch

Run the experiment on a tutorial site and use the preview overlay.

  • Form has no issues
  • Route chosen
  • Hypothesis written
  • Metadata drafted
  • Traffic estimated

Enterprise lens

Experiment log. Record the hypothesis, dates, result and decision so learning is kept.

Collect only the data you need, and publish a privacy notice. Do not expose submission sheets publicly. Check consent requirements before experiments.

Every field needs a visible label and clear error messages. Test forms with a keyboard.

aem.live warns that slow experimentation can cost more than it gains. Avoid blocking calls.
