Operational Telemetry (RUM)

Lab tests show what could happen. Real-user data shows what did.

Operational Telemetry (OpTel) collects a small sample of page views, normally one in 100. It has no concept of visits, visitors or sessions, uses no cookies or similar storage, and sends data with navigator.sendBeacon.

Each data point has an id for the page view and a checkpoint, with an optional source and target. Common checkpoints include top, loadresource, cwv, lcp and viewblock. Each data point carries a weight, so one sample can stand for 100 page views.

You must not add personal data to the collection. Site operators should review the data list to understand whether it needs consent where they operate.

CWV dashboards

A dashboard is useful only if you can tell a real change from sampling noise.

The explorer is at https://www.aem.live/tools/oversight/explorer.html, and most domains need a domain key. It shows traffic, engagement and the vitals LCP, CLS and INP, with a chart and facets. You can share a view by copying the URL.

All data is sampled, so hover over a number to see its margin of error. Filtering narrows the sample and increases uncertainty. Bots that run JavaScript also appear, as a device class.

404 and error monitoring

After any migration, 404s tell you which redirects you forgot.

Your 404 page comes from 404.html at the repository root. Monitor missing pages in OpTel, in analytics, or with Adobe’s Slack bot report, where available. Redirect those that have demand and a good target.

The Admin API has its own errors, documented on aem.live, and Sidekick surfaces common ones. In repoless sites, a fragment can vary the content of the 404 page per site.

Admin logs and status

When a page changes unexpectedly, the first question is who did what, and when.

The audit log records successful preview, live, index, cache, code, config, sitemap and job operations. It includes timestamp, method, route, path, ref and user, which is missing if the request was not authenticated, as well as IP. Reading it needs the log:read permission. Adobe’s page says audit logs are kept indefinitely, or as long as the customer wants.

The status endpoint reports a page’s preview, live and edit state. For events, a webhook can fire at most once a minute, and provides a token for reading changes from the log.

Alerting

Adobe watches the platform. It does not watch your broken checkout link.

Adobe runs synthetic monitors for its multi-tenant services, and for its top 10 customer sites by traffic. Multi-tenant incidents usually appear on status.adobe.com. If Adobe detects single-tenant problems, it will contact you.

So add your own monitoring for the things that matter to you: a few synthetic checks on key journeys through the production domain, certificate expiry, and an alert on telemetry trends. Subscribe to Adobe’s status page. Mind the rate limit of 200 requests per second per IP and host; a misconfigured monitor can trigger it.
