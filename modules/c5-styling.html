Design tokens

Marketing changes the brand blue. With tokens it is one line.

The boilerplate defines design values as CSS custom properties on :root in styles.css, such as --link-color, --body-font-family and --heading-font-size-xl. Media queries can then change the size tokens for larger screens.

aem.live’s advice on naming is plain: keep names simple and intuitive, and avoid namespacing unless the project needs it.

Block-scoped CSS

Blocks share one page, and a stray selector in one can break another.

Every selector in a block’s CSS should only apply to that block, which usually means starting with .blockname. Prefix private classes and variables with the block’s name. Do not prefix those meant to be inherited.

Keep selectors simple: aem.live suggests adding classes during decoration rather than writing complex ones. !important is for very specific cases only.

Section styles

Authors want a coloured band. A section style is simple, if the system is agreed.

A Section Metadata Style row adds classes to the section. Define a small, named set in styles.css, such as .section.light and .section.highlight.

Decoration also adds blockname-container to any section holding that block, and blockname-wrapper to the block’s parent. Use those to adjust layout around a block.

Fonts without CLS

Custom fonts look good, and can make the page jump as they arrive.

Hiding text until the font arrives hurts FCP and LCP. font-display: optional may skip the font and still shift layout. A better way is a font fallback: scale a system font with size-adjust so text occupies the same space.

The boilerplate declares such fallbacks, and loads web fonts after LCP. Adobe has published a Chrome extension to compute size-adjust values.

SymptomCauseFix
CLS after font loadNo fallbackAdd an adjusted fallback.

Design system mapping

A big organization already has a design system. EDS can adopt its values without importing its weight.

Map design tokens from Figma or a token file to CSS custom properties, and generate or copy them into styles.css. Keep only those that the site uses.

Bringing in a full component framework can cost far more than it saves. Translate component specs into blocks, and consider web components only for widgets shared across teams.

Hands-on lab: restyle a site with tokens

Goal

Rebrand a boilerplate site without editing every block.

You need

A project, aem up and a sample brand.

Time

About 75 minutes

  1. List brand values in a mapping table.
  2. Update :root in styles.css.
  3. Replace hard-coded values in blocks with tokens.
  4. Add one section style, and test it through Section Metadata.
  5. Self-host a font and add it to fonts.css.
  6. Add an adjusted fallback.
  7. Check CLS in Lighthouse.

Expected result

A rebranded site with no block-level colour values.

How to verify

A search for hex colours in blocks finds nothing unintended, and CLS stays near 0.

Stretch

Support a second theme with the theme metadata class.

  • Tokens applied
  • Blocks use tokens
  • Section style works
  • Font added with fallback
  • CLS checked
