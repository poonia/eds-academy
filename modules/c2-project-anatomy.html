Folder layout

Finding your way around an unfamiliar project should take minutes. Every EDS project has nearly the same shape.

Every file in the repository is available on your site at the matching path, so /scripts/scripts.js is served from each branch URL. Blocks live in blocks/<name>/, shared JavaScript in scripts/, CSS in styles/, and fonts and icons in their own folders.

A few files are special: head.html, 404.html and .hlxignore. Site configuration now lives in the Configuration Service rather than in repository files, although older projects may still have them.

Core scripts: aem.js, scripts.js, delayed.js

Almost every performance bug starts with code in the wrong file. Know what each one is for.

aem.js is the shared library, and scripts.js is your entry point with the three phases. Older projects and many tutorials use delayed.js for the last phase.

The current boilerplate has no delayed.js. Its loadDelayed() imports consent-check.js, which loads consented.js once consent is granted. Check which pattern your project uses before adding code.

SymptomCauseFix
Tutorial mentions a missing delayed.jsOlder project layoutUse the current consent pattern, or create the file deliberately.
Upgrade conflictsProject edits in aem.jsKeep custom code in scripts.js.

Styles

CSS that loads too early delays the page. CSS that loads too late makes it jump. The three global files exist to get that right.

styles.css holds design tokens and critical styles, and is linked from head.html. lazy-styles.css is loaded during the lazy phase for anything not needed above the fold. fonts.css is loaded without blocking LCP, and a block’s CSS loads with the block.

The boilerplate is mobile first, with a min-width style breakpoint at 900 px for its type sizes.

FileLoadsContains
styles.cssIn headTokens, base layout
fonts.cssAfter LCP on most visits@font-face rules
blocks/x/x.cssWith the blockThat block only
lazy-styles.cssLazy phaseEverything non-critical

Keep styles.css small. Everything in it travels before LCP.

SymptomCauseFix
Styles flash on loadCritical rule is in lazy stylesMove only what is needed above the fold.

UE model files

In AEM-authored projects, three JSON files decide what authors can do. They are code, and they deserve code review.

The xwalk boilerplate has component-definition.json, component-models.json and component-filters.json at the project root. They are generated from models/_*.json and fragments such as blocks/hero/_hero.json.

The build:json script merges them with merge-json-cli, and a Husky pre-commit hook runs this. Edit the fragments, not the generated files.

Hands-on lab: map a real project

Goal

Trace how one page loads through a real repository.

You need

A clone of aem-boilerplate, and DevTools.

Time

About 40 minutes

  1. Open head.html and list what it loads.
  2. Open scripts.js and find the three phases.
  3. Read consent-check.js and run a page with ?consent=accept.
  4. Open the Network panel and match requests to files.
  5. Write a .hlxignore entry for a test file.
  6. Confirm the file is no longer served after you push.

Expected result

A one-page diagram of what loads and when.

How to verify

Each request in the Network panel matches something in your diagram.

Stretch

Compare with the xwalk template and list the differences.

  • Traced head.html
  • Found the three phases
  • Tested the consent gate
  • Excluded a file

Enterprise lens

Upgrades. Keep project logic out of aem.js, and track boilerplate changes deliberately.

The boilerplate head includes a Content Security Policy. Check it before adding inline scripts or third-party sources.

Each file in the head is on the critical path. Change head.html rarely.

Set the page language in your loading code when you support several languages.
