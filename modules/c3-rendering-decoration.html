Delivered markup

If you code against what you see in the DOM inspector, you will misread what the server sent. Start with View Source.

Every page has the same shape: a head with title, metadata and head.html, then an empty header, a main with content, and an empty footer.

In main, each top-level div is a section. A block is a div with the block name as its class, containing a div per row and per cell. Default content is plain semantic HTML.

Decoration pipeline

Most block bugs are order bugs. If you know the sequence, you know what exists when your code runs.

decorateMain in scripts.js runs five steps in order: decorateIcons, buildAutoBlocks, decorateSections, decorateBlocks and decorateButtons.

This happens in the eager phase, and the body is hidden until then, which avoids early image downloads and layout shift. After that, the first section is loaded with priority for its first image, the LCP candidate.

SymptomCauseFix
Button class is missingLink is not alone in its paragraph, or lacks bold or italicAuthor it as a standalone bold or italic link.

Block loading

Blocks are loaded on demand. Understanding how keeps both the critical path and error handling honest.

loadBlock sets data-block-status to loading, then fetches blocks/name/name.css and dynamically imports name.js in parallel. If the module has a default export, it is called with the block element, and the status becomes loaded.

A failure in one block is caught and logged, so the rest of the page continues. Sections load one by one, and the first section is awaited before lazy loading starts.

Auto-blocking in code

You want every article to have a header block, without asking authors to add it. This is where you implement that.

Add your logic to buildAutoBlocks. Use buildBlock(name, content) to create the markup a block would have had from the server, then insert it into main.

The current boilerplate auto-loads links to /fragments/ and builds widget blocks here. Keep this code tiny, because it runs before LCP, and wrap it in a try/catch as the boilerplate does.

SymptomCauseFix
Page crashes on odd contentNo guardCheck elements exist, and keep the try/catch.

Signature interactive: decoration step-through

Step through what happens to one small page.

The server sends sections as plain divs in main.

Icon spans receive their images.

Links to fragments and other patterns become synthetic blocks.

Content is grouped in wrappers, and sections start hidden.

Blocks are marked, and their wrapper and section gain classes.

Standalone links in bold or italic become buttons.

The block’s CSS and JS load, decorate() runs, and the section appears.

Enterprise lens

Shared code review. Auto-block logic affects every page. Require review and test on several templates.

Everything in decorateMain runs before LCP. Measure before adding to it.

Moving content with auto-blocks changes reading order. Keep DOM order sensible.

Treat authored content as untrusted when you build HTML strings. Prefer DOM APIs to innerHTML.
