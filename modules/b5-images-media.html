Images in content

An author uploads a 12 MB photo and worries the page will be slow. On EDS, the platform handles most of that, and the author’s job becomes alt text.

Drag or paste an image into a document. On preview it goes to the Media Bus, stored once with a unique hash in its media_ URL, so it can be cached permanently. Resizing it in the document has no effect.

By default an image renders as a <picture> with a 750 px version for mobile and a 2000 px version for desktop, as WebP with a fallback to the original format. Images are lazy-loaded by default, and the boilerplate makes the first one eager because it is the likely LCP element. Always set alt text.

Video and embeds

A product video should not delay the page or leak data to third parties before consent. How you add it matters.

Word and Google Docs do not take dragged videos directly. Add the MP4 through SharePoint or Drive, preview and publish it with Sidekick, and put the resulting URL as a link in a suitable block.

The block collection includes Video and Embed blocks. Which ones you have depends on your project. Third-party players carry cost and privacy implications, so check with your developers how consent and loading are handled.

Icons and SVGs

Marketing wants a new icon this week. Icons can be managed as content, without code changes.

Reference an icon by name with colons: :phone:. The boilerplate turns this into a span and inserts the matching SVG.

Icons used inside blocks usually live in code. Icons authors add and update can live with content in an /icons/ folder in the content source, and are referenced the same way.

In the documentIcon file
:phone:/icons/phone.svg
:tfsa-badge:/icons/tfsa-badge.svg

:phone: Call us at 555-0100

AEM Assets integration

Brand approved 40,000 images in AEM Assets. Authors need those, not copies from their desktops.

In Word or Google Docs, the AEM Assets Sidekick plugin adds a button, often called “My Assets”, for choosing approved assets. It supports AEM Assets as a Cloud Service and Assets Essentials, and authors must be entitled through a product profile.

With the Universal Editor, related assets are published with the page. A technical account needs access to the asset folder, and assets must fit Edge Delivery limits. Experience Workspace has its own AEM Assets integration (module B6).

Hands-on lab: audit a page’s media

Goal

Check how real images are delivered and fix authoring issues.

You need

A published page with images, and browser DevTools.

Time

About 40 minutes

  1. Open a page and the Network panel, filtered to images.
  2. Find a media_ URL and note its width and format.
  3. Resize the browser below and above 600 px, then reload.
  4. Check the first image has loading="eager".
  5. Check alt text on every image.
  6. Add one icon using the colon notation and preview it.

Expected result

A list of each image, its rendition and whether it has useful alt text.

How to verify

You can state why each visitor receives the rendition they do.

Stretch

Rename a media URL for a friendlier “Save as” file name.

  • Found media_ URLs
  • Compared breakpoints
  • Confirmed first image is eager
  • Audited alt text
  • Added an icon

Enterprise lens

Brand control. Source images from AEM Assets where brand or rights approval matters, and record usage rights.

Describe what an image communicates. Decorative images need no description; charts need the data in text.

Media is same-origin and cached permanently because its URL is content-based. Keep video off the top of the page.

Removing an image from a document does not recall URLs already shared. Use your takedown process for sensitive media.
