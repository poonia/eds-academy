Editor basics

A team likes documents but is outgrowing shared drives. Document Authoring keeps the feel of a document, in a browser tool built for EDS.

Document Authoring (DA) at da.live is a browser editor for EDS, and aem.live now presents it as Experience Workspace. You can enable the upgrade on an existing project when ready: nothing is migrated, and existing work and integrations keep working. This module uses both names.

The editor has a menu at the top, the editing area, and a toolbar. Menus are contextual, palettes stay open and menus close after a click. Experience Workspace adds Layout mode for WYSIWYG editing, alongside Content mode. The blocks you can pick depend on your project’s library.

Versions and restore

A well-meaning edit removed a legal paragraph last week. Version history shows who did it, and restores it.

Versions are created automatically on actions such as preview, publish, translation or rollout, and Snapshot Launches. You can also make your own at any time.

Open the tools panel and choose Versions to see the history in reverse chronological order, including who edited and when, and to restore an earlier version. The current version is shown in a file’s details in the content browser.

Make a named version before a large rewrite, so that you have a clear point to go back to.

SymptomCauseFix
Restored text is not on the siteNot previewed and publishedPreview and publish after restoring.

Library and templates

Authors should begin from approved blocks and page starters, not a blank page or a guess.

The library palette gives authors the blocks and other items set up for the project, and library plugins can add tools such as tag pickers. Because the library is configured per project, what you see depends on your setup.

Starter documents give new pages the right structure. Agree with your team where they live and who owns them. The template metadata property is separate: it tells code how to treat a page (module B4).

Bulk and translation tools

Forty pages need publishing and translating for a launch. Doing it one at a time invites mistakes.

The Bulk Operations app (under Apps) acts on a list of URLs. In the content browser, select pages and use Share to copy their URLs, or use the Traverse tool to list content below a folder.

Translation uses Google Translate out of the box with no configuration. Connectors exist for Lionbridge, Smartling and Trados, and you can build your own. Snapshots group changes so that they can be reviewed and go live together.

ConnectorOffers
Google TranslateDefault machine translation
Lionbridge, Smartling, TradosAI, human and machine translation
SymptomCauseFix
Bulk tool finds nothingList contains the wrong kind of URLCopy URLs with Share.
Machine translation is off-brandNo review stepAdd human review for key pages.

DA with Universal Editor

Some teams want documents with a more visual, form-driven editor. aem.live now has a clear recommendation for where to begin.

Universal Editor can be set up on a da.live site. It needs a DX Handle with Universal Editor enabled (currently requiring AEM Sites credits), Author Bus-compatible instrumentation, and component model files such as component-models.json.

aem.live recommends Experience Workspace rather than Universal Editor for new projects. Existing Universal Editor customers do not have to change, and can move at any time.

Support model

A vice president asks, “If this breaks at 2 a.m., who answers?” Have an answer before the launch, not after.

aem.live uses a seven-stage adoption arc. On 8 November 2026, Experience Workspace was shown at stage 3, Increasing use. That describes adoption and does not promise a support level. We found no aem.live page that states its SLA, so ask Adobe and keep the answer in writing.

Two limits are worth recording. Experience Workspace works only with the EDS document-based repository, so AEM-authored content would have to move. Features such as Request Publish need onboarding with your Adobe contact.

Support terms vary and change. Confirm them with your Adobe account team, and record the date you checked.

SymptomCauseFix
No path when something failsSupport model was never checkedGet terms in writing and log them.

Enterprise lens

Decision record. For each site, log the authoring tool, lifecycle stage, support terms, owner and next review date.

AI assistants can draft quickly and be wrong. Require human review for regulated content, and control who can publish.

Layout mode shows appearance, not heading order. Check structure in Content mode as well.

The editor does not change delivery. Page speed depends on blocks and images.
