Spreadsheet JSON

A sheet is an API that non-developers can edit. Your block just needs to read it well.

Fetch the .json path of a previewed sheet. Single sheets return data, columns, total, offset and limit. Multi-sheet responses add :names, with each sheet under its own name.

Use limit and offset for large data, since a response cannot exceed 6 MB compressed. All values are strings, so convert them.

Query index

A related-articles block needs a list of pages. The index already has it.

/query-index.json lists published pages with the configured properties. The Index Admin tool defines these properties, and a custom index uses a CSS selector to extract values from the page.

Multi-value properties such as tags are delivered as a JSON string, so parse them. Indexes can grow large, so request a sensible limit and filter on the client. Cache in memory if several blocks need the same data.

Limits that shape your design

A single index stops at 50,000 pages, although you can configure several. It contains the same published pages on aem.page and aem.live, so a previewed page never appears until it is published. Unpublishing removes a page. After changing the properties, run Reindex from the Index Admin tool, or existing rows keep their old shape.

Placeholders in code

Hard-coded “Read more” buttons are a translation bug waiting to happen.

Placeholders moved from the boilerplate to the block collection. Copy placeholders.js into your project and import fetchPlaceholders. Pass a prefix such as en for a locale folder, or nothing for the root.

JSON2HTML overlay

Thousands of product pages from a JSON API should be real, indexable pages.

JSON2HTML is a generic worker that turns JSON into HTML pages for EDS. You prepare a Mustache template and add an overlay to your content source pointing at the worker. Then POST a configuration of paths, endpoints and templates to its /config/ endpoint.

Preview a path that matches, and the HTML is generated and ingested, after which everything works as with any other page.

SymptomCauseFix
Page has old dataNot previewed againPreview it when the data changes.

BYOM content source

The content lives in another system, and migrating is out of scope. EDS can read it anyway.

Bring Your Own Markup lets any source publish to EDS, using HTML as the format. For each previewed page, your service returns HTML following the semantics of sections, blocks and default content.

Extra elements, spans, data attributes and styles are removed on ingestion. Images must be reachable by EDS, and are downloaded at preview. Block class names may contain only alphanumerics and single dashes, and may not start with a digit.

How the request is built

When a page is previewed, the admin service requests {origin}{path}{contentPath}{suffix}{params}. With a source of https://content-service.acme.com/data?foo=bar and suffix .html, previewing /products/widget requests https://content-service.acme.com/data/products/widget.html?foo=bar.

BYOM can be a site’s primary source, or an overlay on another source. An overlay suits cases like product pages published from a commerce backend. It needs the Configuration Service, because fstab.yaml does not support it.

Custom index properties and expressions

The built-in properties cover metadata. When a list needs a value from the page’s body, you write an expression.

A custom property has a CSS selector and an expression. select matches all elements, and selectFirst takes only the first. value returns a string, and values returns an array of all matches.

Selectors run against the delivered HTML, not the decorated DOM. Write them from view source. That is the single most common mistake. Not every CSS selector is supported, so check with aem up --print-index, which prints the result for the page you open.

Expressions can be combined. Useful functions include textContent, innerHTML, attribute, match, words, characters, replace, replaceAll, parseTimestamp and dateValue.

Each published page’s result is also available from the Admin API at /index/<org>/<site>/<branch>/<path>. Older projects held these definitions in helix-query.yaml, and new ones use the Index Admin tool or Configuration Service.

Data loading patterns in blocks

Several blocks fetching the same large file, or a list built on every keystroke, is a quiet way to harm a fast site.

Share one request. Keep a promise per URL at module level, so that all blocks on a page reuse one fetch and one parse.

Page the data. Use limit and offset, and loop until you have what you need. Fetching in pieces also means you can stop early.

Convert types once. Everything in sheets is a string, and multi-value columns are a JSON string. Normalize rows as you read them, so the rest of the block deals with real values.

Debounce. For filters, wait for the visitor to pause. Keep filtering on the client, using data you already have.

Limits that affect data design

Limits usually surface months after launch, when an index or sheet has quietly grown. Designing for them is much cheaper.

aem.live says limits exist for stability, can change, and can often be raised for a customer. Treat these as design inputs. Split an index by section or language well before it gets near 50,000 pages. Keep a large file out of the browser by paging or by building a smaller derived index.

Throttled preview operations return a 503 with an x-error header that names the content source’s limit, so bulk scripts must back off. See C11.

Hands-on lab: build a data-driven list

Goal

Build a filterable article list from the index.

You need

A site with a few published pages.

Time

About 90 minutes

  1. Add a title, image, description and tags to several pages.
  2. Configure an index, then reindex.
  3. Open /query-index.json.
  4. Create a block that fetches and lists pages.
  5. Add a tag filter.
  6. Handle failure and an empty list.
  7. Check its performance and placement.

Expected result

A list that updates when you publish.

How to verify

Publish a new page and see it appear without a code change.

Data contracts. Document sheet columns and JSON shapes, and name an owner.

Avoid loading a whole index for one small list.
