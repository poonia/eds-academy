Sidekick customization

Authors repeatedly need one project-specific action. A plugin puts it on their toolbar.

Customize Sidekick with a sidekick object in site configuration. Plugins have an id, a title, and options such as environments (dev, edit, admin, preview, live, prod, any) and includePaths.

A plugin can open a URL or fire a custom event. Sidekick also emits events such as previewed, published and env-switched, which project code can listen for.

Admin API scripting

Publishing 3,000 migrated pages by hand is not a plan.

The Admin API at admin.hlx.page supports status, preview, publish, code, cache, index, config, log and job operations. Authenticate with an API key in X-Auth-Token or Authorization: token. Create keys with only the roles needed.

Rate limits apply: handle 429 responses and back off. Bulk endpoints run as asynchronous jobs, and return a job link to poll.

DA apps and plugins

Authors need a custom tool, with access to protected content.

The Experience Workspace App SDK lets you build fullscreen apps and library plugins. An app is a page and a script on your site, such as /tools/tags.html and /tools/tags/tags.js.

The SDK is based on the postMessage API and lets a tool work with protected content. Import https://da.live/nx/utils/sdk.js as a module.

Edge workers

Some logic must run before the page, for all traffic, without slowing the origin.

If you bring your own CDN, its edge workers can handle live-traffic integrations such as protected APIs. Cloudflare is one documented option for connecting a CDN to EDS, and aem.live’s integration guide lists edge workers for live traffic and author-side tasks.

Keep them small and independent of slow backends, and cache carefully: varying a response by user reduces the cache hit rate. Personal data must not end up in shared cache.

Use forAvoid for
Protecting API keysRendering every page
RoutingLong-running work
Header logicPer-user HTML in cache
SymptomCauseFix
Cache hit rate fallsToo many variationsReduce what the response varies by.

Shared code across sites

Copies of a codebase drift apart. Repoless removes the copies.

Repoless runs many sites from one codebase. All but the first site need no repository. Profiles group reusable configuration, such as headers, indexes and additional metadata, for several sites in an organization.

For local work, use aem up --url to choose a site. For publish events, aem.live has a webhook and audit log; its GitHub Actions publication events carry a deprecation notice. Be careful: a code merge reaches every site at once.

Hands-on lab: script a safe bulk preview

Goal

Preview a list of pages with a key that has limited roles.

You need

A test site and an admin who can create a key.

Time

About 75 minutes

  1. Create an API key with only the roles you need.
  2. Store it in an environment variable.
  3. Check status for one page.
  4. Preview one page and read the response.
  5. Script a list with a pause between calls.
  6. Handle 429 and other errors.
  7. Rotate or delete the key.

Expected result

A safe script with error handling.

How to verify

Each page in your list shows a new preview timestamp.

Stretch

Use a bulk job endpoint and poll the job link.

  • Limited key
  • Key not in git
  • Errors handled
  • Key rotated

Enterprise lens

Automation inventory. List scripts, keys, owners and expiry dates.

Keys are shown once, and expire. Store them in a secret manager and rotate them.

Custom tools are used by authors with disabilities too. Apply the same standards.
