Install and add a project

A new publisher opens a preview and sees no toolbar. Almost always, the extension is missing or the project has not been added.

AEM Sidekick is a browser extension for Chrome and Chromium-based browsers, installed from the Chrome Web Store. In Microsoft Edge, first turn on Allow extensions from other stores at edge://extensions.

Once installed, it hovers near the bottom of pages authored with AEM. Add projects from its menu. A project must be added to your configuration for Sidekick to work on your production, custom preview or custom live URLs.

Preview, publish, unpublish, delete

An outdated rate must come down now, without losing the draft. Choosing unpublish rather than delete is the difference between a quick fix and lost work.

Preview regenerates the page from the source. Publish makes the preview version available in live and production. Visitors see nothing until you publish.

Unpublish removes a page from live and production but keeps it on preview, and needs the publish role. Delete removes it from every environment, and needs the publish or author role. You must be signed in for both, delete is only offered from preview, and neither can be undone.

Unpublish is missingNot signed in, or hidden in the ellipsis menuSign in and open the ellipsis.

Bulk operations

A rebrand touches 80 documents. Opening each one takes the afternoon; a bulk action takes a minute, and can publish a mistake just as quickly.

Open Sidekick in Google Drive or SharePoint and select files to preview or publish them together, or copy their URLs. Sidekick shows the count, asks you to confirm and then reports the status. Green means done; red means some failed and Details explains why.

You can also bulk preview and publish media files. In SharePoint, selections of more than 60 files may not be available to Sidekick, so split them into smaller batches.

Bulk preview first, spot-check with Open URLs, then bulk publish.

SymptomCauseFix
Only part of a selection actsMore than 60 files in SharePointWork in smaller batches.
Bulk result is redSome files failedOpen Details, fix them, then retry those files.

Block library

Authors should not need to remember that it is Cards (dark) and not Dark Cards. The library lets them browse and copy the right table.

The Sidekick Library extension shows authors a browsable list of blocks and their variations. Developers set it up with a workbook, commonly at /tools/sidekick/library.

Each sheet in the workbook is a plugin, and its name must start with helix-, so the blocks plugin uses a sheet called helix-blocks. Each block needs its own example document.

Sign-in and permissions

By default anyone with access to a document can preview and publish it. Regulated teams need to narrow that.

By default authors do not need to sign in to use Sidekick. Adding access statements to the site configuration turns on authentication, with the provider following your setup: Adobe for AEM or Document Authoring, Google for Drive, Microsoft for SharePoint.

Roles are assigned under access/admin, to individuals or wildcard domains. The first Microsoft sign-in may need consent from a directory administrator.

Hands-on lab: take a page through its full lifecycle

Goal

Move one test page through every state and observe each environment.

You need

Sidekick and a tutorial site you can publish to.

Time

About 40 minutes

  1. Install Sidekick and add your project.
  2. Preview a test document and open the aem.page URL.
  3. Change a sentence, then compare preview before and after Update.
  4. Publish and check aem.live.
  5. Unpublish, then confirm aem.live no longer has it but aem.page does.
  6. Bulk preview three documents and copy their URLs.
  7. Delete the test page only.

Expected result

You have seen the page in each state.

How to verify

The aem.page and aem.live URLs match the table in topic 2 after every action.

Enterprise lens

Separation of duties. Give most authors the author role and a smaller group publish.

Unpublish and delete cannot be undone. Double-check the URL first.

Review the preview with a keyboard before you publish.

Publishing triggers cache purges for what changed, so publish in deliberate batches during a large migration.
