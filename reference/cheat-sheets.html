A1 What EDS is and where it fits

Names

  • Helix → Franklin → AEM EDS (Oct 2023) → EDS
  • hlx.page/live → aem.page/live
  • Admin API: admin.hlx.page

Versus traditional AEM

  • No publish tier or Dispatcher
  • Blocks in vanilla JS and CSS
  • Push to GitHub = deploy

Versus headless

  • HTML first, JSON when needed
  • Sheets, CFs, JSON2HTML for data
  • Use both: EDS web, APIs apps

Fit and licence

  • Strong: public, content-led, speed-critical
  • Weak: logged-in, per-user logic
  • Needs AEM Sites licence; dev is free

Lifecycle

  • Build on Mainstream
  • Pilot young features with an exit plan
  • Check deprecations regularly

A2 Core architecture

Sources

  • AEM + Universal Editor (and DA)
  • SharePoint, Google Drive
  • BYOM; not GitHub markdown

Buses

  • Source → Content / Media
  • Code per branch
  • Config with profiles

URLs

  • {branch}--{site}--{org}.aem.page
  • … .aem.live for live
  • Production via CDN

Admin API

  • admin.hlx.page
  • POST /preview, POST /live
  • DELETE /live = unpublish; GET /status

Caching

  • Publish → push invalidation
  • Merge to main → code purge
  • media_ URLs cached forever

A3 Web performance fundamentals

Core Web Vitals (Good)

  • LCP ≤ 2.5 s
  • CLS ≤ 0.1
  • INP ≤ 200 ms

Lighthouse

  • 100 on mobile
  • PSI check on every PR
  • Lab plus field data

Phases

  • Eager: up to LCP
  • Lazy: rest of page, fonts
  • Delayed: third parties, 3 s+ after LCP

Budget

  • < 100 KB before LCP
  • One host before LCP
  • No preload, preconnect, early hints

Code style

  • Vanilla JS, ES modules
  • Per-block loading
  • No build step
