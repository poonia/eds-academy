Glossary

102 Edge Delivery Services terms, each linked to the module that teaches it.

#ABCDEFHIJLMNOPQRSTUW

#

.hlxignore
Lists repository files that should not be served. C2

A

Admin API
The HTTP API at admin.hlx.page for preview, publish, status, code, cache, index, log, config, sitemap and job operations. A2
AEM Code Sync
The GitHub app that syncs a repository's branches to the Code Bus whenever you push. A2
AEM Sidekick
A browser extension authors use to preview, publish and unpublish document-based content. A4
AEM Sites
Adobe Experience Manager's web content management product. Edge Delivery Services is part of AEM Sites and requires an AEM Sites licence. A1
aem-embed
A web component that embeds EDS content in other sites and applications. D10
aem.live
Live domain for Edge Delivery Services sites, formerly hlx.live. Also the home of the official documentation. A2
aem.page
Preview domain for Edge Delivery Services sites, formerly hlx.page. A2
AGENTS.md
A file that tells coding agents about a project’s structure and conventions. E6
AODA (Accessibility for Ontarians with Disabilities Act)
Ontario law requiring organizations to meet accessibility standards; for websites the benchmark is WCAG 2.0 AA. A1
API service (Admin service)
The service that previews and publishes content: it pulls from the content source into the Content Bus and promotes content to live. A2
App Builder
Adobe’s serverless platform for custom applications and integrations. C9
App SDK
The Experience Workspace toolkit for fullscreen apps and library plugins. E8
Audit log
A record of successful admin operations such as preview, publish and configuration changes. D7
Auto-blocking
Code that turns default content and metadata into blocks early in page decoration. B1

B

Block
A component authored as a table whose first row names it; code in blocks/<name>/ decorates it on the page. B1
Block Collection
Adobe’s public repository of reusable blocks that projects copy and adapt. C4
Boilerplate
Adobe's starter repository for EDS projects, with aem.js, scripts.js, styles and sample blocks. A3
Branch URL
A URL of the form {ref}--{site}--{org}.aem.page that serves one code branch, so every branch is its own environment. A2
Bulk metadata
A sheet that applies metadata to pages by URL pattern. B3
BYO CDN (Bring your own CDN)
Using your own production CDN (Akamai, Fastly, Cloudflare or CloudFront) in front of EDS instead of the Adobe-managed CDN. A2
BYOM (Bring your own markup)
A content source option where your own service supplies HTML that EDS ingests. A2

C

Canonical site
In repoless, the site whose org and name match the GitHub owner and repository. D1
CDN (Content delivery network)
A network of edge servers that caches and serves content close to visitors. A2
Challenger
A variation tested against the current experience, the control. B10
Closed User Groups
Page-level access rules that are enforced at the CDN. D4
Cloud Manager
Adobe's console for AEM as a Cloud Service programs and pipelines; since 2026.4.0 it can create Edge Delivery sites. A1
CLS (Cumulative Layout Shift)
A score for how much visible content moves unexpectedly while a page loads. Good is 0.1 or less. A3
CMP
Consent management platform: software that records a visitor’s privacy choices. C9
Code Bus
Storage for JavaScript, CSS and other code, kept per branch so each branch is its own environment. A2
Component model
Field definitions that drive the Universal Editor Properties panel. B7
Config Bus
Storage for site and organization configuration, which can inherit from a profile. A2
Configuration service
The Admin API-backed service that stores organization, profile and site configuration, enabling repoless sites. A4
Container block
A Universal Editor block with its own properties and child items. C7
Content Bus
Storage for previewed and published content (text, PDFs, SVGs, redirects), with preview and publish lifecycle states. A2
Content Fragment (CF)
A structured, reusable piece of content in AEM defined by a model; it can be published to EDS as semantic HTML. A4
Content source
The system where authors create content for an EDS site: AEM with Universal Editor, Google Drive, SharePoint, Document Authoring or a bring-your-own-markup source. A2
Core Web Vitals (CWV)
Google's three user-experience metrics: LCP for loading, CLS for visual stability and INP for responsiveness. A3
CSP
Content Security Policy: a browser control over which scripts and resources can load. D4

D

Default content
Headings, paragraphs, lists, images and links written with normal formatting, outside any block. B1
Delayed phase
The third loading phase: third-party tags, consent and analytics, loaded well after LCP. A3
Design token
A named design value, held on EDS as a CSS custom property. C5
Dispatcher
AEM's caching and load-balancing module that sits in front of the traditional AEM publish tier. A1
Document Authoring (DA)
A browser-based, document-style editor at da.live built for EDS. Adobe now presents it as Experience Workspace. A4
Domain key
The key that opens a domain’s data in the Operational Telemetry explorer. D7
Drop-in
A ready-made package that provides the interface and logic for one Commerce shopper job. E3

E

Eager phase
The first loading phase: everything needed to reach LCP, including the first section and the LCP candidate. A3
Early access
Edge Delivery Services feature stage where a capability is available to customers but may still change significantly and need extra support. A1
Edge Delivery Services (EDS)
Adobe's edge-rendered publishing and delivery service for websites, part of AEM Sites. It turns authored content into fast, semantic HTML served from a CDN. A1
Element grouping
Combines several elements into one cell, using an underscore in the field name. C7
ES modules
JavaScript's native module system (import and export), which browsers load without a build step. A3
Experience Workspace
Adobe's newer name and expanded authoring surface for Document Authoring, adding a visual canvas, AI assistance and MCP connections. A4

F

Fallback font
A local font sized to match a web font so text does not jump (CLS) when the web font loads after LCP. A3
Field collapse
Combines model properties into one element using suffixes such as Alt, Title and Type. C7
Fragment block
A block that places a separately published piece of content on a page. B4
Franklin
A later internal project name for Edge Delivery Services, used publicly as "AEM Franklin" before the October 2023 rename. A1
fstab.yaml
The older in-repository file that mapped a site to its content source. With the configuration service (Helix 5) it is no longer required. A2

H

Headless CMS
A content system that stores structured content and delivers it as JSON through APIs, leaving rendering to a separate front end. A1
Helix
Internal Adobe project name behind the technology that became Edge Delivery Services; it survives in names such as hlx.page and admin.hlx.page. A1
hreflang
Links equivalent pages across languages, generated through the sitemap on EDS. B9

I

INP (Interaction to Next Paint)
Time from a user interaction to the next visual update. Good is 200 milliseconds or less. A3

J

JSON2HTML
An Edge Delivery Services overlay that renders EDS-friendly HTML pages from JSON data at any endpoint. A1

L

Lazy phase
The second loading phase: project-controlled resources served mostly from the same origin, such as later sections and remaining images. A3
LCP (Largest Contentful Paint)
Time until the largest image or text block in the viewport is painted. Good is 2.5 seconds or less. A3
Lighthouse
Google's lab tool that scores page performance, accessibility, best practices and SEO from 0 to 100. EDS targets 100 on mobile. A3
Live
The published stage of content, served on an .aem.live host and through the production CDN. A2
Live Copy
Content kept in sync with its source by Multi Site Manager. B7

M

MCP (Model Context Protocol)
An open protocol that lets AI tools connect to systems such as AEM to read and manage content. A4
Media Bus
Content-addressable storage for images and media. Each asset is stored once under a hash with a media_ prefix, so it is immutable and can be cached permanently. A2
MSM (Multi Site Manager)
AEM's feature for managing live copies of content across sites and locales. With EDS it is combined with repoless setups. A4
Mustache
A simple template language used to turn JSON into HTML. E5

N

noindex
A robots value that keeps a page out of search results and the sitemap. B3

O

Operational Telemetry
Sampled performance data from real visits, collected without cookies. C6
Origin selector
A CDN rule that sends matching requests to another origin. D3
Overlay
A second content source that is checked before the primary source. E5

P

PageSpeed Insights (PSI)
Google's service that runs Lighthouse and reports field data. The AEM GitHub bot runs it on pull requests. A3
Path mapping
Configuration that relates AEM content paths to public URLs. B7
Payload
The total bytes a page downloads. aem.live advises keeping the payload before LCP under 100 KB. A3
Placeholders
Site-wide strings kept in a sheet with Key and Text columns. B3
Preview
The review stage of content, served on an .aem.page host after an author previews a page. A2
Profile
A configuration-service object holding reusable settings (headers, indexes, metadata) that sites in an organization share. A site has at most one profile. A4
Push invalidation
Automatic purging of CDN caches when content is published, so the CDN can cache for a long time without serving stale pages. A2

Q

Query index
A JSON list of published pages used for lists, feeds, search and filters. B3

R

RACI
A matrix of who is Responsible, Accountable, Consulted and Informed for each decision. D9
Repoless
Running several sites from one codebase: only the first site has a GitHub repository; the others point to it through configuration. A4
Request Publish
An Experience Workspace approval workflow that needs onboarding by Adobe. B8
Rule Editor
A no-code tool for adding conditions and actions to forms. E4
RUM (Real user monitoring)
Performance data collected from real visitors' browsers. In EDS this is called Operational Telemetry. A3

S

Section
A part of a page separated by a horizontal rule (---) in documents; it wraps default content and blocks. B1
Section Metadata
A table inside a section that adds classes, an ID or data attributes to it. B1
Semantic HTML
HTML that uses elements for their meaning (headings, lists, main) so browsers, search engines and assistive tech understand it. A1
Sidekick Library
A Sidekick extension that lets authors browse and copy blocks. B2
Significance
A check of whether a difference between variants could be luck. E1
Single host rule
aem.live guidance that, before LCP, only one host should carry network payload, so early connections to other hosts are avoided. A3
Site token
A credential that gives read access to a protected site. A CDN sends it to a protected origin. D2
Snapshot
A group of content changes that are reviewed and released together. B6
Source Bus
Storage that holds documents and spreadsheets in their authored form. Only the API service can access it. A2

T

Third-party script
Code loaded from another company's host, such as tag managers, chat widgets or ad pixels. A3

U

Universal Editor (UE)
AEM's WYSIWYG editor for in-context editing with a properties panel; content is stored in AEM and published to EDS. A4

W

WCAG (Web Content Accessibility Guidelines)
The W3C accessibility standard. WCAG 2.2 AA is the common enterprise target. A1
Web SDK
Adobe Experience Platform’s client library for analytics and personalization. C9
Widget
A self-contained, application-like feature, as distinct from a content block. E10
